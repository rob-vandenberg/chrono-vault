# D-037: export in the reference program's format

**Taken in autonomous mode** (G-26) on 22 November 2026, within the owner's changelist (items 1 to 5); Q38 answered by
the owner: the master password first, a plain warning, the whole vault with the Trash and the Archive.

## What was decided

1. **File > Export…**, while a vault is unlocked: the window says in bold that the export holds every password
   unencrypted, asks for the master password, and only then "Export…" chooses where to save it. A wrong master
   password, or a folder that cannot be written to, is said in that window and nothing is written.
2. **The format is the reference program's JSON, exactly as Chrono Vault's importer reads it** (D-035): every item,
   field, section, hidden and deleted field, history, attachment, custom and website icon, category and template of
   the person's own, and tags as nested folders. What Chrono Vault never kept is filled in as the reference program
   writes it (an attachment's kind from its file type, an icon's file name).
3. **The reference program's format has no field roles**: after an export and an import a built-in field such as
   "User name" comes back with the same name, type, value and marks, as a field of its own. Everything a person sees
   is the same; the tests export, import again and compare exactly that.
4. **The file is written safely** (`QSaveFile`), off the window's thread (OR-5), and **readable by the person alone**,
   as a new keyfile is too.
