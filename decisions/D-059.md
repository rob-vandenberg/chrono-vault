# D-059: PIN unlock

Approved by the owner on 24 November 2026 (Proceed, version 0.4.70), from his mockup of Settings > Security and his
answers Q4 to Q8 of that day. The reference program's documentation answered the rest (OR-16): a PIN unlocks only
while the program keeps running, the master password at every start; the PIN may hold letters as well as digits; with
the fingerprint on as well, the finger is asked first.

## What was decided

1. **Settings > Security in the owner's order**: Change the Master Password; Ask for the master password again, once
   every; Autolock when; the PIN; the fingerprint; Hide sensitive fields.
2. **The PIN line**: a tick box "Use a PIN code to quickly unlock without having to enter the Master Password every
   time", its text on two lines, and the PIN field at its right. Kept with OK, like the other settings of the window.
3. **The PIN field** shows dots, as password fields do; the eye only while a new PIN is typed, never otherwise (the
   owner). The PIN itself is never kept, so it can never be shown again.
4. **A PIN holds anything the person wishes**, at least 4 characters (the owner). OK stays grey while the box is ticked
   without a PIN set or one of 4 or more typed. Unticked, OK removes the PIN and all that was kept for it.
5. **The PIN only while Chrono Vault runs**: at every start the master password; after that, every lock offers the PIN
   for each vault unlocked meanwhile. When the master password is due again ("once every"), it is asked instead.
6. **The unlock page**: the field reads "PIN"; Enter unlocks; "Use master password instead" below it.
7. **Wrong PINs follow the owner's wait rule** (D-041), in the same count per vault as wrong master passwords.
8. **Changing the master password keeps the PIN working.**

## How it is kept (the coder's, within the changelist)

1. A key is made from the PIN with Argon2id, with the cost a new vault gets; its salt and cost are kept in
   `chrono-vault.conf`.
2. On disk each vault keeps the PIN's key only sealed with the vault's own key: a stolen disk with a short PIN opens
   nothing, as `test_pin_unlock` checks.
3. While a vault is unlocked, the PIN's key is held, and the vault's key is kept in memory sealed with it; at a lock the
   PIN's key is wiped. After a start, a vault's own master password gives the PIN's key back from its entry.
4. A vault gets its entry when it is unlocked while the PIN's key is known: when the PIN is set (the vault open and the
   primary), and at each unlock after that. A vault first unlocked straight after a start, before any vault with an
   entry, gets one only the next time it is unlocked while the PIN's key is known.
5. A key that no longer opens the vault (its master password changed on another computer) drops that vault's PIN, and
   the person is told to type the master password.
