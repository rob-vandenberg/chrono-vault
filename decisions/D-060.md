# D-060: The vault menu in Settings > Vaults

Approved by the owner on 24 November 2026 (Proceed on changelist items 1-22, versions 0.5.75 to 0.5.77, in autonomous
mode), from his answers Q26 to Q38 of that day and his mockup review.

## What was decided

1. **Each vault in Settings > Vaults has a ⋮ menu** in place of the buttons Move to WebDAV… and Disconnect…. The menu
   shows only the actions that can be done to that vault now; an action that cannot be done is not shown (the owner,
   Q35). A vault with nothing to offer has no ⋮.
2. **Lock**: shown only for the vault that is unlocked; it locks it.
3. **Move…**: between any places the program supports (the owner, Q37): this computer to this computer, to WebDAV,
   WebDAV to this computer, WebDAV to WebDAV. Select Storage asks where to, then the file here or the WebDAV folder.
   The vault is locked by itself when the move starts, so nothing changes while it is copied (the owner). The copy is
   written, read back and compared, and only then the original is deleted (OR-15). A move that fails or is stopped
   leaves the vault where it was.
4. **Forget…**: takes the vault off the list. Never shown for the primary (the owner, Q26). A local vault's file stays
   where it is. A WebDAV vault's working copy on this computer is deleted at once, with any change not yet on the
   server (the owner, Q27 and Q29: his exception to OR-15); the vault on the server stays.
5. **Disconnect…**: for a vault on any cloud storage. From then on there are two separate vaults: this computer's and
   the remote one. Nothing is deleted, on any storage (the owner, Q28; again for Google Drive in 0.8.119): there is no
   tick box to delete. The dialog, in three paragraphs with the storage and the vault filled in (the owner's words,
   0.8.119): "Chrono Vault keeps a local copy of every vault that is stored in a remote location, like Google Drive, so
   you can keep working while you are offline. Changes are synced automatically once your connection is restored." /
   "Disconnecting from the remote vault makes the local copy a separate individual vault. Both vaults continue to exist
   and nothing is deleted, but changes in one vault are no longer synced with the other vault." / "This action cannot
   be undone. Are you sure you want to disconnect from “<vault>”?"
6. **Vaults that cannot be found are listed**, struck through and marked "Not found", with only Forget… (the owner, Q36).
7. **The Sync conflicts dialog** (0.5.76), after Chrono Mail's (the owner, Q34 and Q38): Tools > Sync Conflicts…
   lists every item with a conflict (What, Name, Fields, Where, Why, with a legend); the ticked rows are settled whole
   with Use value now, Use other value or Keep both; Check all and Invert selection; a double click opens one item's
   conflict: each value that differs outlined, the value now and the other value, nothing chosen beforehand, Apply once
   every row is chosen; Keep both keeps the item and a copy with the other values. An item deleted on one side and
   changed on the other is kept, or moved to the Trash (never deleted for good). It replaces the note on the item of
   D-054: the item shows "This item has a sync conflict." with Settle…. A sync never asks: a conflict waits until the
   person settles it, and the newest value stands meanwhile, the other kept with it (OR-15).
8. **Import… and Export…** (0.5.77). Import… opens one window, from File > Import… (into the open vault) and from
   a vault's menu (into that vault; the owner, Q32 and Q33): first where from, another vault (from the list, or any
   vault file with Browse…, with its master password) or an export made elsewhere (the reference program's), then
   the summary and Import. The import adds items; an item the vault already has is never written over: the same, it
   is passed over; different, the vault's values stay and each value that differs is a conflict marked "Imported",
   settled in the Sync conflicts dialog, which opens after the import (the owner, Q34). Items deleted in the other
   vault are not deleted here. Export… of a vault's menu opens the File > Export… window for that vault. A vault that
   is not open is unlocked first with its master password in a small window, and is then the vault shown.

## How it is kept (the coder's, within the changelist)

1. The copy of a move is compared byte for byte with the vault it was read from; the vault is not decrypted, so a
   move needs no password. A copy that reads back the same opens as the original did.
2. A WebDAV vault is moved from its server's version, which holds what other devices sent. A WebDAV vault whose
   working copy holds a change not yet on the server is not moved: the person is asked to unlock it so it
   synchronizes first.
3. A copy to a WebDAV server is put under a passing name, moved into place, and read back; a broken-off upload never
   stands under the vault's name, and a failed or stopped move removes what it put there.
4. The list names the new place before the original is deleted, so a program that stops in between leaves both
   copies, never none. When the original cannot be deleted (a file in use, the server unreachable), the move is done
   and the person is told to delete the old copy.
5. A moved vault keeps its own settings: its keyfile, its PIN entry, its count of wrong master passwords (a move never
   starts the waits again, D-041). The finger's key is kept again at its next master-password unlock (D-043).
6. A moved vault's password saved in the primary follows it: at once in memory, and in the primary's item the next
   time the primary is unlocked.
7. A vault being moved is not unlocked until the move is done.
8. An import compares an item the vault has by its title, subtitle, note, website and field values: those are the
   conflicts. What only the import holds is added with nothing to choose: a field, an attachment, a tag, an earlier
   value in a field's history. A different category, Trash or Archive stays as the vault has it, as a sync settles
   them (D-054 point 4). An item the vault deleted for good and an import brings back stays: its deletion is
   forgotten, so no sync takes it away again silently.

## Taken in autonomous mode

1. Q39: Forget… on the vault open now locks it, forgets it, and shows the primary's unlock page.
2. Q40: Import… from another vault offers the list of vaults and a Browse… for any vault file (0.5.77).
3. Q41: the Sync conflicts dialog's sides read "Value now" and "Other value" (for an import, "Imported"), not "This
   device" and "Other device" as recommended: a conflict travels with the vault to every device, so which device a
   value came from cannot be told on another device.
4. Moving compares bytes instead of decrypting the copy (How it is kept, point 1).
5. A WebDAV vault with a change not yet on the server is not moved (How it is kept, point 2).
6. Retry sync and Keep here only of Chrono Mail are left out: a WebDAV server takes or refuses the whole vault, never
   one item. Dragging the columns is left out too; their widths are fixed shares.

**Since 0.5.78 (D-061)** an import no longer adds what only it holds, nor passes over a difference in category, Trash,
Archive or the like: every difference waits in the Sync conflicts dialog, whose sides read "Vault" and "Import".

**Since 0.6.100 (D-071): a vault's menu begins with Open or Lock, by its state; a right click on its row opens it.**

**Since 0.6.103 (D-073): Open, Import… and Export… of a vault ask in the standard dialog.**

**Since 0.6.105 (D-074): a vault's menu has "Make primary vault".**

**Since 0.6.106 (D-075): Close and Lock, each for the one vault.**

**Since 0.8.128: Forget and Disconnect ask the password of a vault that is not open (the owner, 27 November 2026).**
The open vault's user is its owner and needs no password; a closed or locked vault could be someone else's. So for a
closed or locked vault the Forget and Disconnect dialogs hold, under their question, the line "Enter the password to
forget the vault" or "…to disconnect the vault" ("Master Password" for the primary), the password field and its
keyfile, as Delete does (D-083); the button works once the password is typed and acts only when it is right. A vault
whose file is not on this computer cannot be proven and is forgotten without a password.
