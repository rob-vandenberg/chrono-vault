# D-035: importing the reference program's export

**Taken in autonomous mode** (G-26) on 22 November 2026, within the owner's changelist; the owner's rule: import
exactly as the reference program would, identical in every way. The format was learnt only from the owner's own
export, through scripts that wrote shapes, never values, to files the owner checked before they were read.

## What was decided

1. **File > Import…**: the person picks the reference program's JSON export; it is read off the window's thread
   (OR-5), and a window sums up what it holds (items, attachments, categories and templates of the person's own).
   Only Import adds it to the open vault, in one save, as safe as every save (OR-15). A lock closes the window and
   drops what was read.
2. **Everything is imported** (the owner): every item, the Trash and the Archive included; an item whose id the vault
   already has gets a new id and never goes over another.
3. **Kept as the export has it**: titles, subtitles, notes, favourites, Autosubmit, times; every field in the
   export's order (equal orders keep their place), with its type, label, value, hide mark, id, time and history;
   sections; hidden fields (types starting with a dot) and deleted fields, never shown; a field type Chrono Vault does
   not know is kept as text, value and all.
4. **Categories and templates**: the export's built-in ones map to Chrono Vault's; one of the person's own becomes a
   category of their own, named as the export names it, and its template one of their own, made from the fields of
   its first item, empty. Those already in the vault are not made again.
5. **Icons**: a custom icon (PNG written as hexadecimal) is matched by its uuid and kept as given; an item with a
   website's icon keeps its site, for website icons (D-036).
6. **Attachments** (base64) within Chrono Vault's limits (D-029); tags, when an export has them, nested as there.
7. **A damaged export is refused whole** and said; the vault stays as it was (OR-4).
8. **OR-7**: the reference program is named only as quoted text in the importer's source file and its test; the
   import window takes the name from it, so no other file, translations included, holds it.

**Since 0.5.77 (D-060)** an item the vault already has is no longer imported again under a new id: the same, it is
passed over; different, each value that differs is a conflict settled in the Sync conflicts dialog (the owner, Q34).
