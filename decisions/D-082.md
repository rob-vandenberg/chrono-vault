# D-082: One design for every dialog

Approved by the owner on 27 November 2026 (Proceed in autonomous mode on the changelist of version 0.8.120; Q5, Q7 and
Q8 of that brainstorm). Before it, an inventory of every dialog from a clean start, at 100% and 200%, found 13
different widths, empty bands, fixed content that remembered a size, and buttons of different sizes at different
distances from the edges.

1. **A dialog of text, a few fields and buttons** (the default, `fitsContent: true` in `qml/DialogWindow.qml`) is
   **440 pixels wide** at 100%, times the UI scaling. Its texts wrap within that width and its fields fill it; it is
   exactly as tall as its content, never resized, and remembers no size. A text taller than the screen scrolls inside
   the dialog.
2. **A window with a list, an editor or a file view** says `fitsContent: false`: the person resizes it and finds it
   at that size again, under a memory name of its own (no two windows share one). These are Open a vault, Settings,
   Sync conflicts, Sync conflict, the WebDAV and the Google Drive file dialogs (each its own size), Choose Icon, the
   template editor, About, Import and a field's history.
3. **One edge on all four sides**: 12 pixels at 100%, the bottom too, so the last button is exactly as far from the
   right edge as from the bottom. Settings has the same edge.
4. **The bottom row's buttons are alike**: each as wide as the widest in the row (at least 80 pixels), the same
   height, 6 pixels apart, at the bottom right. This is built once, in `qml/DialogWindow.qml`; a button the dialog
   hides (Import's own OK) takes no room.
5. **Texts**: a text of more than one paragraph shows its paragraphs half a line apart (`DialogWindow.paragraphs`);
   no text is bold as a whole; every password field shows its placeholder in the normal font and the password in the
   monospaced one.
6. **The password and PIN dialogs** (unlock, import, export, retry sync, WebDAV password, PIN; `qml/AskWindow.qml`)
   take this design too (Q8): their question as normal text, normal fields, the vault in a normal field.
7. **The two key dialogs** of Settings > Keyboard are dialogs of this design; Cancel in "Press the new key" never
   takes the keyboard, so every key arrives as a key.
8. **One window used for two dialogs** (Open a vault and Create a vault on the start page) keeps each its own size: a
   new memory name reads what is kept under it (`src/ui/window_memory.cpp`).
9. **WebDAV and Google Drive go straight to the file dialog** (Q5): once connected or signed in, the file dialog opens
   by itself; it is then the only window seen. A choice there goes on at once (a new vault to its master password,
   Open to the unlock, Move to the move); Cancel there ends it all. The Vault or Folder field and Browse… are gone;
   after a choice that failed, the window's button reads Browse… and opens the file dialog again.

Tests: `test_dialog_design` and `test_dialog_design_200` (every dialog: 440 wide and fixed to its content where it
fits, the bottom row alike, the same distance to the right and the bottom), `test_webdav_windows` (Create and Move fit,
Open keeps its size; WebDAV and Google Drive straight to the file dialog, Cancel ends it all; Disconnect in three
paragraphs), `test_appearance`, `test_dialog_keys`, `test_vault_rows`.
