# D-040: Change the Master Password in Settings, and Autolock when

Approved by the owner on 22 November 2026 (changelist items 21 to 27, Proceed); the details below taken in autonomous
mode (G-26) are marked so.

## What was decided

1. **Settings > Security > Change the Master Password**: a row with a Change button, opening the same window as File >
   Change Master Password; greyed while no vault is unlocked.
2. **Autolock when**, in Settings > Security, as in the reference program:
   1. Main window is closed (switch, off): the vault locks when the window is closed into the tray.
   2. System sleeps (switch, off): the vault locks when the computer goes to sleep.
   3. Chrono Vault is idle for N minutes (tick box, on, 5): the earlier "lock after this many minutes without use".
   4. System inactive for N minutes (tick box, off, 10): the vault locks after that long without keyboard or mouse
      input anywhere on the computer.
3. Where the desktop does not tell the system's inactive time, that row is greyed with a line saying why.

## Taken in autonomous mode

1. A setting of 0 minutes from before (then "never") becomes "Chrono Vault is idle for" unticked at 5 minutes.
2. Linux: logind's PrepareForSleep for sleep; the inactive time from `org.freedesktop.ScreenSaver.GetSessionIdleTime`
   (KDE and others; on KDE with X11 in milliseconds, checked) or GNOME's `org.gnome.Mutter.IdleMonitor.GetIdletime`.
   Windows: the power message of going to sleep, and `GetLastInputInfo`. Both asked without waiting on the window's
   thread; the inactive time every 30 seconds, only while a vault is unlocked and the choice is on.
3. Waking from sleep locks too, when that choice is on, in case going to sleep was not seen.
4. "System inactive for" is offered at 10 minutes when ticked (the reference program's picture shows the owner's 100).
5. The system's inactive time counts only from the last unlock on: an unlock by finger is no input the system sees.
