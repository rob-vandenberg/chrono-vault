# D-030: several vaults

**Taken in autonomous mode** (G-26) on 22 November 2026, within the owner's changelist for `ROADMAP.md` steps 6 to 9;
as in the reference program wherever its documentation answers.

## What was decided

1. **Chrono Vault keeps a list of the person's vaults.** Every vault created or opened joins it. The first is the
   **primary vault** (ref), also while its file is on a drive that is not there at the moment; the one vault of an
   older version becomes it.
2. **The vault at the top of the left column chooses among them**, and offers New vault… and Open vault…; so does the
   File menu, also while a vault is unlocked. An edit not saved yet is asked about first; a change still being saved
   holds the switch up, with a message ("Wait until your last change is saved"). **Since 0.7.110 (D-078)** a vault that
   opens without a password is opened before the one shown closes.
3. **A new vault's password can be saved in the primary vault** (ticked by default, ref), as a Password item whose
   "Vault file" field names the new vault's file. The person sees and can change it like any item.
4. **Switching**: the primary opens with the key kept from this session, without asking; a vault whose password is
   saved in the primary opens with it; any other asks for its own password. The primary's key and the saved
   passwords are kept in memory only while a vault is unlocked.
5. **Locking locks every vault** (ref): the primary's master password is asked, and once it is unlocked, the vault
   that was shown comes back. When the primary's file is not there, the lock stays on the vault shown. A change kept
   through the lock (D-016) stays kept until its own vault is unlocked.
6. **What cannot be used is said**: a password saved in the primary that no longer opens its vault is forgotten and
   named as the saved one; a primary changed elsewhere asks for its master password; a new vault whose password could
   not be saved in the primary stays in the list, and the failure is said on the primary, where it can be tried
   again. Changing a vault's master password also changes the copy saved in the primary.

## Changed by D-058 (version 0.3.64, the owner)

Point 5: a lock no longer brings the primary back; the unlock page keeps the vault used last, with a dropdown of
every vault, and its own master password opens it.

**Since 0.6.105 (D-074): another vault can be made the primary; a typed password can be remembered in it.**

**Since 0.6.106 (D-075): a lock keeps in mind how the vault was opened; its primary comes first again.**
