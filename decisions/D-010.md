# D-010: releases and the Windows twin

Approved by the owner on 21 November 2026, before any code existed.

## What was decided

1. **The Windows version is built on a Windows twin of the Linux machine**, which holds a copy of the project folder
   with the same layout. Its name, address and paths are details about the owner's computers and live only in the
   project's private folder (G-1, G-17).
2. **Four scripts**, all written by the coder and modelled on the owner's Chrono Viewer, all private (OR-9):
   1. `push-to-development.sh` copies the project to the Windows twin. **The coder runs it automatically after every
      code generation**, so the twin is never behind.
   2. `gitpush.sh` pushes to GitHub, once the repository exists.
   3. `build-release.sh` builds the `.deb` and the `.rpm` into the project's own `dist/` folder and, once the
      repository exists, creates the GitHub release and adds them to it.
   4. `build-release.bat`, run on the Windows twin, builds the Windows setup and adds it as an asset to the GitHub
      release created by `build-release.sh`. **It checks the version on GitHub and attaches the setup only to the
      release with the same version number**; when there is none, it stops and says so.
3. **Releases go into `dist/`**, here and on the Windows twin.
