# D-012: the source layout, and the vault core apart from the windows

Approved by the owner on 21 November 2026 with the changelist of `ROADMAP.md` step 1. The owner left the choice to the
coder; the coder chose this.

## What was decided

1. **The vault core is a library of its own, `src/core/`, in plain C++ with Qt Core only.** It holds no window code
   and is tested without a screen.
2. **The windows are one QML module, `qml/`** (URI `ChronoVault`), in Qt Quick (D-003). They only call the core.
3. **The program itself, `src/app/main.cpp`**, starts the windows.
4. **Tests**: `tests/unit/` for one class each, `tests/integration/` for pieces together; Qt Test under CTest, at most
   20 seconds each, never a window on the screen (OR-11).
5. **Qt 6.8 or newer** (the owner's answer), C++20, CMake 3.21 or newer; warnings are treated as errors for our own
   code; a sanitizer build (AddressSanitizer and UndefinedBehaviorSanitizer) with the option `CHRONO_VAULT_SANITIZE`,
   built into `build-asan/`.

## Why

1. The vault, and with it the person's data, never depends on the window code. Should the window toolkit ever change,
   the core stays untouched (the continuity concern behind D-002).
2. The core is easy to test without a screen, which never-lose-data (OR-15) and never-crash-on-input (OR-4) need.
3. The same core can serve all five platforms (D-001), whatever each one's windows look like.
