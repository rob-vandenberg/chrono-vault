# D-021: the update check and the update itself

Approved by the owner on 21 November 2026 (changelist of version 0.0.5).

## What was decided

1. **Settings > General: "Check for updates"**, Daily, Weekly, Monthly or Never; Daily at first, as in Chrono Viewer.
   The automatic check runs shortly after the start when the chosen time has passed since the last check GitHub
   answered, and again every hour while Chrono Vault runs. A failed automatic check stays silent and is tried again.
2. **The About box**, opened with F1 for now (the user interface comes later), as in Chrono Viewer and the owner's
   mockup (changed with version 0.0.8): the icon at the top left with the name, the version and the copyright beside
   it; below them, across the whole width, a read-only, scrollable text area with every licence Chrono Vault ships:
   our own AGPL-3.0 first, then, each after a horizontal bar and a line naming what it covers, Qt's LGPL-3.0, GPL-3.0
   and GPL-2.0, OpenSSL's Apache License 2.0 and the Noto fonts' SIL Open Font License 1.1; on Windows also one line
   for Microsoft's C++ runtime, which comes without a text to ship. The texts are carried inside the program.
   **Check for update** at the bottom left, **Close** at the bottom right. Every dialog keeps the same narrow edge as
   the settings window.
3. **The update works as in Chrono Mail** (the owner's word). Chrono Vault knows how this copy was installed: the
   `.deb` or the `.rpm` (a program in `/opt/chrono-vault` with the system's package record) or the Windows setup (its
   uninstaller beside the program). A copy run from a project folder is never updated this way and says so.
4. **It offers the newest GitHub release above its own version that carries this install's file** (`_amd64.deb`,
   `_x86_64.rpm`, `-setup.exe`), compared number by number. The update window offers **Download** and **Skip this
   version**; a skipped version is not offered again by the automatic check.
5. **The download** goes to the Downloads folder, shows its progress, can be stopped, and is checked against GitHub's
   SHA-256 fingerprint of the file; a file that does not match is never kept or installed. Before installing, the
   file is checked again.
6. **Installing**: on Linux through the system's own software installer (PackageKit), which asks for the password
   itself; then Chrono Vault quits (asking about unsaved work, D-016) and the new version starts once it has ended. On
   Windows, Chrono Vault quits first, then the setup runs silently and starts the new version.
7. **Nothing about the person reaches GitHub**: the requests carry only the program's name and version.
8. **The packages carry what HTTPS needs** (Qt's TLS plugins, and on Linux OpenSSL's `libssl`), and the bare-system
   checks of `build-release.sh` try one real request with `chrono-vault --check-for-update`.
