# D-061: The person decides every difference

Approved by the owner on 24 November 2026 (Proceed on the changelist of version 0.5.78, in autonomous mode), from his
answers on P54 and Q45 to Q57 of that day.

## Why

**Any choice the program makes could be the wrong one.** It can never know beyond reasonable doubt which of two values
is right: only the person knows which PIN the bank has, or that a deletion was a mistake. So the program never judges,
never guesses and never decides: it shows the difference, keeps both sides safe, and waits for the person (the owner).

## What was decided

1. **An import**: an item the vault does not have is imported; an item only the vault has stays. An item in both that
   differs is a conflict, every difference a row the person settles: title, subtitle, notes, website, category,
   template, Trash, Archive, Favorite, Autosubmit Login and icon; a field's value, name and hide mark; a field deleted
   on one side and present on the other, either way and also when the values are the same (P54); a field only the
   import has; an earlier value only the import holds; a tag or an attachment only the import holds, or the same
   attachment with other content; an item the vault deleted for good that the import still holds (Q45, Q47, Q51).
2. **A sync between devices**: a change made on one device only is taken without asking (the owner's own example,
   Q52). Whatever both devices changed differently, and with no shared earlier version every difference, is a
   conflict the person settles, in the same ways as for an import (Q46). D-054 point 3 and its "Taken in autonomous
   mode" point 4 no longer stand.
3. **The two sides' names** (Q50, Q54, Q55, Q57): for an import "Vault" and "Import", the buttons "Use Vault" and
   "Use Import"; for a sync "This device" and "Other device", the buttons "Use This device" and "Use Other device".
   "Where" stays as it was (Q56).
4. **Until the person chooses, both sides are kept** (OR-15): the value standing in the item, the other in the
   conflict, attachments included.
5. The conflict window's header choices stand in line with the rows' (P53); the row tick boxes of the Sync conflicts
   list are as clear as Check all.
6. With it, in the same version: Choose the master password shows "Keep this vault's password…" before "Also lock the
   vault with a keyfile"; texts in dialogs wrap with the window and no dialog can be made narrower than its content
   (Q48); the menus of the menu bar have a colour of their own, apart from the sidebar and the window.

## How it is kept (the coder's, within the changelist)

1. `src/core/item_differences.cpp` compares two versions of an item for an import and for a merge without a base,
   and puts a chosen other side in place; `src/core/vault_merge.cpp` notes every two-sided difference. A note
   (`MergeNote`) names what differs; the contents format 9 adds a note's subject, its other data (an icon, an
   attachment, a template), the time of an earlier value, the device whose value stands, and the vault's own notes
   for the person's categories and templates. An older Chrono Vault refuses a format 9 vault as made by a newer
   version (OR-4).
2. A field only the other side has is kept on the item as deleted until the person chooses; taking the other side
   brings it back. An attachment replaced by the other side's is kept beside it as "<name> (earlier)".
3. An item deleted here for good and held by an import is kept with its conflict, its deletion forgotten and its time
   set to now, so no sync removes it meanwhile; "Use Vault" deletes it for good again.

## Taken in autonomous mode

1. **This device's value stands until the person chooses** in a sync, also when the other is newer: the merge cannot
   otherwise say which side is "This device". The device is a random id kept in chrono-vault.conf; a note made on
   another device shows its two sides swapped, so "This device" is always this device's value (with two devices;
   with three or more the program cannot know the third's).
2. A merge that finds a change kept through a lock now treats that kept change as this device's ("mine").
3. Only differences the changelist named are conflicts; one only the vault has (a field, tag, attachment or earlier
   value the import lacks) is no difference: an import or the other device simply lacks it.
4. A field's role, kind and hidden type, which no window lets the person change, follow the side that changed them;
   both changed, this device's stands without a conflict, as there is nothing to show.
5. The conflict window says for a sync "Changed on two devices. Nothing is decided until you choose."
6. When the ticked rows hold both an import's and a sync's conflicts, the buttons read "Use Vault / This device" and
   "Use Import / Other device". Keep both is not offered for a category or template.
7. A dialog's smallest width is the width it opens at; it can be made wider, and its texts follow.
8. The menus' colour is the theme's button colour (#35383b dark, #e4e4e4 light), given to the menu as its Base.

## Version 0.5.81: the windows as Chrono Mail's, Retry sync and Keep here only

Approved by the owner on 24 November 2026 (Proceed, in autonomous mode). His principle: an import merges, and its two
sides need not end up the same; a sync keeps two copies the same.

1. **The window of one conflict** shows every field of the item in its order, the same values plain, a difference
   outlined in Chrono Mail's second accent (orange in the dark theme, red in the light one) with a choice in front of
   each side; What, Where, Why and Found; the header's choices take a side for every row. "(empty)", "(deleted)" and
   "(not on the item)" say what a side lacks.
2. **A split** keeps both values of an E-mail, Phone or Web address: a second field with the same name, kind and hide
   mark directly after the original. Ctrl+Z joins the last split again before Apply.
3. **Retry sync** reads the item again from its source and compares afresh: an import's file or vault, or the shared
   vault. An imported vault's key, never its password, is kept sealed in memory until the lock. A source that cannot
   be read is said, and the conflict stays.
4. **Keep here only**: an item deleted on the other device and changed here stays, and the next sync puts it back
   there. An item deleted on one side is settled whole, with the header's choices.
5. Retry sync, Keep here only and Keep both only choose in the window of one conflict; Apply carries them out.
6. **The Sync conflicts list** is a table whose columns are dragged and remembered, with line icons for Why. Its
   buttons are greyed, never hidden. Keep both stays in it (the owner: Chrono Mail's list gets it too).
7. **An item deleted here for good and held by an import is simply imported** (in place of point 1's last case and
   "How it is kept" point 3 above). A field only the import has, once taken, stands where the import has it.

Taken in autonomous mode:

1. An empty field that is the same on both sides, a section heading and a hidden field are not shown, as the item's
   own view does not show them; the category, tags and attachments are.
2. Where an import's value came from is kept in the conflict inside the vault ("from"); the contents format stays 9,
   and an older Chrono Vault that saves the vault loses only Retry sync for it. A conflict made before 0.5.81 has no
   source: Retry sync is greyed for it, and for a category or template an import holds differently.
3. An item that its source no longer holds keeps its conflict, so no value is lost (OR-15).
4. A note of an item deleted on one side says which device deleted it; one made before 0.5.81 reads as deleted on the
   other device. An item brought back since both sides agreed on its deletion is taken by the other device without
   asking (a change on one side only, point 2).
5. A split shows and keeps the value standing first. A built-in field's second one is a field of the person's own
   with its name.
6. An item that changes elsewhere while its window is open is shown anew, with nothing chosen.
7. Retry sync of a sync conflict reads the shared vault as a whole and merges it; a value the other device no longer
   holds there stays in the conflict.
