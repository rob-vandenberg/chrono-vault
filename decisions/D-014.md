# D-014: the vault file

**Taken in autonomous mode** (G-26) on 21 November 2026, within the owner's changelist for the first version.

## What was decided

1. **One file per vault**: a 40-byte header, then the contents sealed with AES-256-GCM (D-013). The header holds the
   letters `CHRVAULT`, the format version, which key derivation and cipher are used, the Argon2id cost and the salt.
   The header is covered by the seal, so a change to it is detected too.
2. **A file that cannot be read is never half-read**: a file that is not a vault, one of a newer format, one that is
   damaged or truncated, or one asking for more than 1 GB of memory to derive its key, is refused with its own reason
   (OR-4). Files over 256 MB are not read at all.
3. **Every save is safe** (OR-15): the new vault is written to a file next to it (ending in `.saving`), flushed to the
   disk, read back and decrypted, and only then put in the old one's place in one step. A save stopped at any point
   leaves the old vault whole; the tests prove it for every step.
4. **While the vault is unlocked, the derived key is kept in memory**, so saving does not ask for the master password
   or derive the key again; it is wiped when the vault locks.
