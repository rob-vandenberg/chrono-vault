# D-029: attachments

**Taken in autonomous mode** (G-26) on 22 November 2026, within the owner's changelist for `ROADMAP.md` steps 6 to 9;
point 3 confirmed by the owner (Q21: "only save as").

## What was decided

1. **An item can carry files**, added in the item editor and kept inside the vault, sealed like everything else
   (`REQUIREMENTS.md` 4.6). They travel with the vault.
2. **At most 5 MB per attachment** (the reference program's limit) **and 150 MB for all attachments of one vault
   together**, so the vault file stays well below the 256 MB that is read at all (D-014). A file over either limit is
   refused, and the person is told which and why.
3. **An attachment is only saved where the person chooses ("Save as…")**, never opened through a temporary file,
   because nothing of the vault's contents is ever written unencrypted on its own (`REQUIREMENTS.md` 4.1).
4. **Nothing slow on the window's thread** (OR-5): a file is read, an attachment written, and the vault's contents
   put into JSON for a save, on threads of their own.
5. **A file added in the editor belongs to the vault only once the item is saved**; it is dropped when the vault
   locks before that, like any other change still in the editor that the person did not save.
