# D-083: Delete a vault

Approved by the owner on 27 November 2026 in the brainstorm after version 0.8.121 (Q1 to Q10 of that chat), through
the Proceed on the changelist of version 0.8.122. The reference program's Remove deletes from the device only, never
the cloud, and never removes the primary; the owner chose to delete for good, on the server too.

1. **Delete…** is in the right-click menu of every vault in Settings > Vaults, for every vault and every state.
2. **The checks, in this order** (Q9). Each says why and has only Close; nothing is deleted.
   1. The primary vault while other vaults exist: "“<name>” is your primary vault and cannot be deleted while you have
      other vaults. To delete it, first make another vault primary with Make primary." (Q8)
   2. An open or a closed vault: "The vault “<name>” is currently open." or "… currently closed.", then "The vault must
      be locked before it can be deleted." Two whole sentences, so translators get each whole.
3. **A locked vault asks**, in the design of D-082: first line in bold "WARNING: You are about to delete the vault
   “<name>”."; then "The vault and all information it contains will be permanently lost!" and "This action cannot be
   undone. Are you sure you want to delete the vault?". The dialog is just wide enough that this question stands on
   one line (the owner, 0.8.123, mockup `28-Delete-the-vault-mockup-2.png`). Above the field: "Enter the password of
   the vault you are about to delete."; the field's hint "Password" for every vault; the vault's own password, never
   the primary's; its keyfile when it has one, "This vault requires its keyfile." (Q7). Delete in red (#ff6b6b) at the far left, usable once a password is typed; Cancel the default at the right
   (Q5). Enter and Esc never delete: Enter in the field does nothing, Enter on Delete does nothing
   (`enterNeverPresses` in `qml/DialogWindow.qml`), Esc is Cancel.
4. **The check**: the password (and keyfile) is proven against the vault's copy on this computer, off the window's
   thread (OR-5). Wrong: the dialog stays, its error line says so, nothing is deleted.
5. **The deletion** (Q2, OR-15), in this order, each step only after the one before it succeeded:
   1. A cloud vault on its server: WebDAV deletes the file, Google Drive puts it in Drive's trash (D-080). When the
      server cannot be reached or refuses, nothing at all is deleted and the reason is shown in the dialog. A vault
      already gone from the server counts as deleted there, so a deletion stopped after this step can be done again.
   2. Its files on this computer: the vault file, and for a cloud vault its local copy and base file.
   3. Everything of it on this computer: its place in the vault list and its cloud place record, its PIN, its kept
      server password or sign-in in the system store, its keyfile entry, its waits after wrong passwords, its finger
      key, its sort order and use counts, "Remember my credentials" off, a move record. Chrono Vault keeps no window
      size per vault, so there is none to remove.
   4. Its remembered password in the primary vault is emptied: at once when the primary is shown unlocked, else when
      it is next unlocked (the list "vaults/deleted" on this computer; the primary's key store never uses it meanwhile).
   Backup files the person made stay, and so does the keyfile, which is the person's own file.
6. **The only vault** (Q10): deleting it leaves the program on the start page (Open a vault / Create a vault).
7. **Stopped at any step** (OR-15.4), nothing that should stay is lost: before the server step nothing is deleted;
   after it the vault stays listed and Delete finishes it; after its files the vault stays listed as Not found, and
   Forget takes it off the list.

**Since 0.8.129: two dialogs, as an extra confirmation (the owner, 27 November 2026).** First the standard password
dialog (D-073): "Delete the vault" / "Enter the password of the vault you are about to delete." / Delete, its field
"Password", for the primary too. Only a right password opens the warning, which no longer holds the field: the bold
WARNING line, the question, Delete in red at the far left, Cancel the default (Enter is Cancel, Esc too). A delete that
fails says why in the warning; Delete is then greyed, and the vault's password is asked again from its menu.

**Since 0.8.130: first the warning, then the password (the owner changed his mind, 27 November 2026).** The refusals
(the primary while other vaults exist, an open or a closed vault) come first, unchanged. A locked vault: the warning,
whose Delete opens the standard password dialog with the words above; only a right password there deletes. A delete
that fails says why in that dialog, and the password can be typed again.
