# D-024: the update's windows, as in Chrono Mail

Approved by the owner on 22 November 2026 (changelist of version 0.0.9). It replaces how D-021 presented an update;
how an update is found, checked and installed stays as D-021 says.

## What was decided

1. **An update is offered in a popup**, "Update available", never as a line in the main window: "Chrono Vault X is
   available. You have Y.", a link "What is new in Chrono Vault X (on GitHub)" (only to Chrono Vault's own release
   pages), and **Download** (the default), **Skip this update** (the owner's words) and **Cancel**. The download's
   progress shows in the same window; Cancel, Esc or closing it stops the download.
2. **Found by an automatic check**, the popup opens by itself without taking the keyboard from someone typing, and
   only while the main window is on screen and the preferences are not open; otherwise it waits until then. **Found
   by Check for update** in About (or Help > Check for update), About closes and the popup comes forward. About shows
   the other answers itself: looking, the newest version already, GitHub not reached, not installed with an installer.
3. **After the download**, a window "Update downloaded": "The update to Chrono Vault X was downloaded and checked: it
   is complete and unchanged.", a link "Saved in <folder>" that opens the folder, **Install** (the default) and
   **Close**. On Linux Install shows "Installing the update… your system may ask for its password." and the window
   cannot be closed while the system installs; a failure says the update is still in its folder and Install can be
   tried again.
4. **Once installed on Linux**, a box "Chrono Vault was updated": "Chrono Vault was updated to X. Restart it to use
   the new version." with **Restart** and **Close**. Chrono Vault closes either way, asking about unsaved work first;
   only Restart starts it again. **On Windows** Install closes Chrono Vault first, then the setup runs and starts it
   again.
