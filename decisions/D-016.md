# D-016: the windows of the first version

**Taken in autonomous mode** (G-26) on 21 November 2026, within the owner's changelist for the first version.

## What was decided

1. **The start page** offers two things: create a new vault, or open one. A new vault is a file ending in
   `.chronovault`, in the place the person chooses (the target "this device" of D-005).
2. **A new vault is never made over an existing file**, whatever it holds; the person is asked to choose another name
   (OR-15). The master password is typed twice.
3. **The last vault is offered again, locked**, when Chrono Vault starts; "Open another vault…" goes back to the start.
4. **The unlocked vault** shows the items on the left, sorted by title and narrowed by a search over title, user name
   and web address, and the chosen item on the right. New logins and secure notes come from the tool bar.
5. **The editor** shows every field with its name. A password is hidden until "Show"; "Copy" copies a field;
   "Generate…" opens the password generator; a one-time code field shows the current code and its seconds left. Custom
   fields of text or password can be added and removed. "Save" stores the item and saves the vault at once; "Delete…"
   asks first.
6. **Every change is saved at once**, off the window's thread; when a save fails, the change stays in the window, the
   vault on disk is untouched, and the person is told so (OR-5, OR-15).
7. **Copying** marks the text as secret, so the clipboard history tools of KDE and Windows leave it out, and clears it
   after 30 seconds unless something else was copied since. **The vault locks** after 5 minutes without a key or mouse
   press. Both are set in the settings window (D-011): Security and Clipboard, 0 meaning never.
8. **Every slow step** (deriving the key, reading and writing the file) runs off the window's thread; the window shows
   a busy sign meanwhile (OR-5).

## Added after the first review (autonomous mode)

9. **Changes are never dropped without asking**: going to another item, making a new one or closing the editor while
   it has unsaved changes asks "Save your changes?" with Save, Discard and Cancel.
10. **Locking keeps what is being typed**: the editor stores it first. A change that could not be saved (a full disk,
    a folder that cannot be written to) is kept through the lock, sealed with the vault's own key so nothing readable
    stays in memory, and saved at the next unlock. While a change is unsaved, the message line offers "Try saving
    again" (OR-15).
11. **The master password for a new vault** is accepted only when both fields hold the same password; a typing slip
    never sends the person back to the start.

## Added after the second review (autonomous mode)

12. **A failed save stays in sight**: the line "A change is not saved yet" with "Try saving again" shows for as long as
    the last save failed, whatever other message comes after it.
13. **Plain information disappears after 5 seconds**; trouble stays until it is resolved.
14. **Closing the window never drops work without asking**: unsaved changes in the editor are asked about as in point
    9, and a change that could not be saved is asked about with Retry, Discard and Cancel.
15. **An existing file is refused as soon as it is chosen**, before any password is typed.

## Added after the third review (autonomous mode)

16. **Closing waits for a save that is still running**, and asks as in point 14 when it fails; closing the main
    window also closes the settings window, so the program ends.
17. **A change kept through a lock is never dropped silently**: the unlock page says it is waiting, and "Open another
    vault…" and quitting ask first.
18. **A new item counts as changed only once something is typed in it**, so an untouched new item is never stored by a
    lock and never asked about.
19. **The item being edited stays highlighted** in the list while searching and saving.

## Added after the fourth review (autonomous mode)

20. **Cancel on a new item that was typed in asks first**, as every change does (points 9 and 18).
21. **A copy kept through a lock is cleared as soon as the save that was running succeeds**, so the unlock page never
    warns about a change that is already on disk (OR-18).
22. **The password generator always keeps one kind of character ticked**, so the password is what the boxes say.
