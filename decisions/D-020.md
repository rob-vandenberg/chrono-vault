# D-020: one Chrono Vault, and windows that remember

Approved by the owner on 21 November 2026 (changelist of version 0.0.4).

## What was decided

1. **One Chrono Vault per person.** As it starts, Chrono Vault looks for a running Chrono Vault of the same person,
   through a local connection only that person can use. If there is one, it is asked to come to the front (shown from
   the tray when it was hidden there) and the new start ends at once. A connection left behind by a Chrono Vault that
   crashed is cleared and never blocks a start.
2. **The main window comes back as it was left**: its size, its place and its state (normal, maximized or minimized).
   "Start Chrono Vault minimized" (D-019) wins over the state that was left.
3. **Every other window the program makes remembers its size and place too**: the settings window, and every dialog,
   which is a window of its own that can be moved and resized (the owner's answer to Q41): the new vault's password,
   the generator, delete, save changes, quit and leave vault. A dialog opens centred over the main window the first
   time.
4. **A place on no screen any more** (a monitor was unplugged) is moved onto the nearest screen, made smaller when it
   is larger than that screen.

## Known limits

Under Wayland a program may not choose its own place nor pull itself to the front: there the size and the maximized
state come back, the place is the desktop's choice, and a second start may only make the taskbar entry ask for
attention. On X11 and Windows everything above works.
