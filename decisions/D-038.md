# D-038: unlocking with a fingerprint

**Taken in autonomous mode** (G-26) on 22 November 2026, within the owner's changelist (items 6 to 13). The owner:
Linux on the weaker terms (Q39), whatever the feature needs may be used (Q43), the reminder once a year (Q44), and
no master password at every start, which goes beyond the reference program (it asks after a restart).

## What was decided

1. **Settings > Security > "Unlock with fingerprint"** (Windows: "Windows Hello"): Turn on / Turn off, per vault, on
   this computer, at once; turning it on needs the vault unlocked and asks for the finger once.
2. **Windows**: Windows Hello (fingerprint, face or PIN) through C++/WinRT. A key credential per vault signs a random
   challenge kept in the settings; the SHA-256 of that signature seals the vault's key. Without Windows Hello there is
   no signature and nothing to open the seal with.
3. **Linux (weaker)**: fprintd checks the finger over D-Bus; the vault's key is kept in the desktop keyring through
   the Secret Service (KWallet, GNOME Keyring), which any program of the person's session can read once the keyring is
   open. The keyring is reached off the window's thread, as it may ask for its password.
4. **What is kept** is the vault's key whole (key, salt, cost, the keyfile mark) and its keyfile's fingerprint, so a
   vault with a keyfile opens too, and a later master password change can still be checked.
5. **At every start and unlock** the finger is asked at once; "Unlock with …" and the master password stay there.
   A cancelled finger says nothing; an unknown finger says so; a key that is gone (fingerprints changed, keyring
   emptied) turns it off for that vault and says to use the master password and turn it on again; a keyring that cannot
   be reached now (its prompt dismissed) leaves it on. A finger scan still waiting is stopped once the vault unlocks.
6. **Changing the master password** keeps the new key for the finger at once: on Linux without asking for the
   finger, on Windows with one Windows Hello check, said beforehand; if that fails, the person is told to turn it on
   again. It also restarts the reminder's year.
7. **The reminder**: once a year since the master password was last typed, the unlock page asks for it though a
   finger would do; "Not now" lets it wait another year; Settings > Security can turn the reminder off. Typing the
   master password resets the year.
8. **Other systems** (macOS for now) have no fingerprint unlock yet; Android and iOS come with their own step.
9. **Tested** with a stand-in for the reader; the real fingerprint is tested by the owner on his two laptops.
10. **Windows Hello on Windows** (the owner, 23 November 2026, version 0.2.53): ticking "Use Windows Hello to unlock
    vault" opens no box of Chrono Vault's own; Windows Hello's window has its own Cancel. While it is open the settings
    window says "Waiting for Windows Hello fingerprint..." in red at its bottom left, and the tick box stays ticked
    only when Hello says yes. Hello is given the Chrono Vault window that has the keyboard as its owner, so it opens
    over Chrono Vault, both when turned on and at the unlock page, where Windows has those calls; an older Windows
    keeps the calls without an owner. Linux is unchanged.
11. **Windows Hello on top on every Windows** (the owner's choice B, 24 November 2026, version 0.4.72). Only Windows 11
    24H2 (build 26100) and newer let a key credential's window be given an owner, so on the owner's Windows 10 Hello
    opened behind Chrono Vault. Now the person is asked through `IUserConsentVerifierInterop`'s
    `RequestVerificationForWindowAsync`, which takes Chrono Vault's window that has the keyboard, on every Windows
    version; once Hello says it is them, the vault's key is opened with Windows' protection for this Windows account
    (DPAPI), kept in `chrono-vault.conf`. Weaker than the signed key it replaces (a program already running under the
    person's account could ask Windows for it), the same kind as Linux's keyring (Q39); chosen because it is one way the
    owner can test whole. A key kept the earlier way is removed with its Windows Hello credential, and the person is
    told to turn Windows Hello on again. After a master password change the key is kept again without asking Hello.
    The "Unlock with Windows Hello" button is as wide as its text, centred (the owner).
